# FellowStudio3D 界面框架与本轮自查

本地开发版，2026-10-27。目标：没有动画经验的人也能理解“现在正在改什么”，常用操作直接可见，详细参数按需展开。保持像素风三栏、四视图与直接拖动。

## 统一归属

| 区域 | 负责什么 | 主要入口 |
| --- | --- | --- |
| 项目栏 | 整套创作的保存、读取、撤销、语言和字号 | 新建、打开、保存、撤销 |
| 创作入口 | 选择资源，以及进入具体创作工具 | 创作资源库、角色模型、UV贴图 |
| 左侧动画 | 基础动作、叠加顺序、全局动画表现 | 动画工具、动作层、复古动画 |
| 中间预览 | 构图、显示、播放和直接操作 | 四视图、显示选项、画幅、取景、时间条 |
| 右侧参数 | 当前选中的动作或控制对象 | 标题说明当前对象，常用参数在前 |
| 角色模型 | 可复用的外形与附属部件 | 外形／头发／耳朵／尾巴／物品 |
| UV贴图 | 外部绘画、贴图替换、共享与像素保护 | 开始／继续绘制、部位卡片 |
| 导出 | 输出目录、名称、视角、格式与倍率 | 单一导出窗口 |

代码中模型导航也收敛为一个当前分类状态，旧辅助接口只是别名，不再维护能同时为真的多个模式开关。

角色决定“长什么样”；动画决定“怎么动”；显示设置决定“画面怎么呈现”；导出设置决定“如何交付文件”。复古动画会改变换姿节奏，所以放在动画表现；光照、阴影、描边和贴图显示放在预览的显示选项。导出视角只在导出窗口选择，不再在预览区放第二个选择器。点击预览焦点仍决定首次导出的默认方向。

## 组件与交互规则

1. **先对象，后参数。** 所有模型部件处于同级页签；不把尾巴藏在躯干末尾、物品藏在手臂内部。外形页才显示身体结构和部位选择。物品页先选择所属手。
2. **三段结构。** 选择／添加部件 → 选择已添加对象 → 常用参数／详细参数。头发模板是创建方式，不能伪装成一直存在的父对象。复制、镜像复制、删除归到当前部件的操作菜单。
3. **复杂度按使用频率展开。** 常用形状、尺寸直接显示；位置、塑形、握持等细节继续按需展开。显示选项默认收起，保证预览空间；展开后光照和贴图开关仍在一起。
4. **按钮是完整操作。** 紧凑按钮使用文本自然宽度，整项换行，不把按钮里的字挤成几行。下拉选择与添加按钮能伸缩同排；标签和对应输入成组换行。强制窄列使用省略号，悬停可看完整文字。
5. **联动和单次对称分开。** “左右联动”表示持续同步，开启时先把当前侧形状同步过去；“对称到另一侧”只执行一次。头发提示关联对象，缺失一侧可以补齐；姿势卡也可选择左右联动，默认不改已有不对称动作。对称外形不等于共享贴图。
6. **明确提交边界。** 模型、贴图、资源搭配、姿势动画在草稿中预览，用应用／取消提交或放弃；光照与画幅明确提示实时生效并支持主窗口撤销。主要提交按钮与取消的位置统一。打开、撤销时以项目值刷新控件，不能让旧控件覆盖新项目。
7. **保存对象说清楚。** 顶部保存是完整项目；模型保存是可复用外观；动画工具中的保存动画是可跨角色迁移的动作；导出的JSON标为项目副本，不再混叫动画配方。
8. **导出是可重复的工作流。** 名称、倍率、视角、格式、子文件夹选项在本次app会话内记住，不加入项目或设置文件；已有目录记忆保持原行为。同名目标询问覆盖，生成成功后才替换。

## 自查结果

| 问题 | 本轮处理 |
| --- | --- |
| 复古动画混在显示开关里 | 移至左侧动画表现 |
| 主工具栏混入大量画面参数 | 顶部保留项目与创作入口，预览显示集中到可收起区域 |
| 头发、耳朵、尾巴、物品层级不一致 | 五个同级模型页签，两个身体结构使用相同导航 |
| 紧凑按钮固定窄宽、文字竖排 | 自然宽度、单行标签、整项换行和截断提示 |
| 工具栏忽略下拉框伸缩 | 根据伸缩项和可用宽度分配行内空间 |
| 时间／FPS等标签与输入分离 | 标签和控件作为一个组参与布局 |
| 动作层没有就地排序和边界状态 | 增加上移／下移，越界和无选择时禁用；保留选中对象并支持撤销 |
| 打开／撤销会被旧显示控件覆盖 | 修正项目→控件同步，连同边线色恢复 |
| 发束联动开启后仍保留旧差异 | 开启即同步当前侧，标明配对，缺侧可补齐 |
| 耳朵缺失一侧难以补回、形状入口不一致 | 补齐／单次对称，增加圆耳／尖耳形状选择 |
| 姿势卡只能整张镜像，缺少局部关联 | 增加四肢／成对发束的单次镜像与可选持续联动，拖动同样生效 |
| 尾巴只能通过重建换类型 | 当前尾巴可切换形状，保留尺寸与位置；仍在应用前预览 |
| 模型导入入口重复 | 统一到角色库→载入文件，保存模型仍独立可见 |
| JSON导出命名与实际内容不符 | 改名为JSON项目副本，保留现有文件兼容性 |
| 连续导出反复配置 | 本次会话记忆；同项目保留自定义输出名，换项目默认新项目名 |
| 同名导出只能失败 | 询问覆盖；暂存生成、备份替换、异常恢复，仅清理该名称和所选格式的旧文件 |

## 验证与边界

用实际Tk窗口检查主界面、显示区、模型页签、资源库、姿势卡、绘画与导出流程，覆盖窄窗口、字号缩放和中英日文本。截图只获取临时测试窗口自身，不读取其他应用。布局检查验证边界、重叠、完整按钮标签；行为检查覆盖取消、应用、撤销、对称联动、连续导出和覆盖确认。

覆盖已有文件时，先完成全部输出，再备份相关旧文件并发布新文件；生成或发布失败会恢复备份。对其他格式与其他名称的文件不做清理。此为应用级失败回滚；如果系统连恢复操作也阻止，会保留备份目录并提示位置，不删除唯一备份。不宣称多个文件在系统掉电时具备数据库式原子性。

本轮不更改动画算法、公共角色目录或旧项目格式。多个尾巴仍共用原有尾巴动画通道；模型内部的逐步撤销没有新增，草稿仍可整体取消。后续新增功能需先说明所属对象与流程位置，避免重建隐藏的“杂项”区域。


## 小屏幕自动适配（2026-10-27）

主窗口以 Tk 的逻辑尺寸计算可用空间，启动时及窗口尺寸变化后自动降低控件缩放，
侧栏按预算收紧，优先保留中央预览。移除主窗口固定 1100×720 下限，较小屏幕
允许缩至 820×560；Mac 额外预留菜单栏与 Dock 空间。缩放变化防抖，自动适配
不覆盖用户保存的偏好；A−／A＋可继续手动调整。窗口放大后恢复到偏好上限。
界面缩放不会改变项目画幅、像素渲染或导出尺寸。


### 2026-10-27 缩放触发修正

默认保留大尺寸（1.5）或用户手动偏好，不再按窗口宽高预先压低字号。启动布局
稳定后，仅当实际渲染区宽度低于240或高度低于140逻辑像素时启动保底缩小；
触发后恢复至280×180以上就停止，最低比例0.75。不自动覆盖手动字号偏好。
